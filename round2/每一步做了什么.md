## 第 2 步 · 在迟交上赢过简单规则（方向 1）

**做了什么**
- 发现第一轮的 `lateness` 设置实际上就是“最早完成”，所以必然打平。
- 试了多种规则（`实验/lab_allocators.py`），选定三步规则：① 留下返工后仍按时的车间；② 其中选用途最窄的；③ 再相同选最早完成。
- 做了穷举（`实验/lab_floor.py`），看“事后最优”能到多少。
- 另外生成三族新数据（seed 20000 起，规则定下来之后才生成）做验证（`实验/validate_allocators.py`）。

**结果**（`02_分配器/分配器v2_结果.md`）

| | 简单规则 | 新规则 |
|---|---|---|
| 官方 120 单，迟交率 | 1.67% | 1.67% |
| 官方，迟交天数 | 0.178 | 0.091 |
| 官方，平均周转 | 8.3 天 | 9.3 天 |
| 官方 shock，迟交率 | 1.92% | 2.00% |

**没做到**

- 简单规则周转快 1 天、缺陷件数占比低 0.5 个点，shock 下迟交率也略低。这些在文档里都写明了。

## 第 3 步 · 修已知缺陷（方向 3）

| 缺陷 | 改法 | 验证 |
|---|---|---|
| 承诺的日期有 6% 守不住 | 估算器多给一个“如果返工”的日期 | 1,200 批里返工日期 100% 守约（shock 99.2%） |
| 解释只说“最早按时完成” | 一句“为什么选它”，并写出最快的是哪家 | 测试 |
| 拆单问题没有回答 | 明确回答“不用拆”或给出拆法 | 测试 |
| 约束的时间看不出来 | 记录谁、哪条消息、几点；晚于请求到达的会写明 | 测试 |
| “上周那张大单”查不到候选 | 订单查找支持“上周”“最大” | 评估里的“回复完整”一项 |
| 订单表里没有的新活被问“哪张已有订单” | 新活问件数和交期 | 测试；挑战集 C06 C24 C32 |
| 同一张单能被派两次 | 派单前查账本 | 测试；挑战集 C25 |
| 刷新后有数字无法追溯 | 约束作为一次工具调用记录 | 测试：刷新和一键确认后 30 条全部可追溯 |

测试从 25 个加到 56 个，全部通过。

## 第 4 步 · 语言层的证据（方向 2）

**做了什么**
1. 写评估脚本 `eval/run_language_eval.py`：字段、行为、决策、解释四项分开打分。决策由 `eval/independent.py` 检查，它是另写的一份实现，不调用系统代码。
2. 先写 38 条挑战集（`03_语言层评估/挑战集/`），再测基线，然后才改语言层。
3. 测基线：规则解析器、GPT-5 nano、GPT-5 mini，各在两套消息上。
4. 改进：提示词 v2；代码核对（模型提取的每个值对照消息原文，原文没有的丢掉）。
5. 读错误，补了两次核对规则（2.1、2.2），每次都把两个模型在两套消息上重跑 3 遍。
6. 做了消融：只换提示词、只加核对，各自贡献多少。
7. 搭了留出集骨架：44 个格子，四位写手每人一张表，另两位同学全程不看。

**结果**（`03_语言层评估/语言层评估_结果.md`；行为 % / 字段 % / 决策 %）

| | 官方 30 条 | 挑战集 38 条 |
|---|---|---|
| 规则解析器，改动前 | 100 / 100 / 100 | 84.2 / 94.5 / 86.4 |
| GPT-5 nano，改动前 | 85.6 / 91.5 / 88.3 | 84.2 / 92.1 / 84.8 |
| GPT-5 mini，改动前 | 100 / 98.0 / 100 | 96.5 / 97.6 / 100 |
| GPT-5 nano，最终 | 100 / 99.1 / 100 | 97.4 / 98.5 / 98.5 |
| GPT-5 mini，最终 | 100 / 99.2 / 100 | 100 / 99.2 / 100 |

回答你中途问的两个问题：
- **要不要编对话来测？** 要。官方 30 条系统是照着做的，规则解析器在上面 100%，一换说法就掉到 84%。所以编了 38 条。但我编的不能算最终测试，最终要同学手写的留出集。
- **换更聪明的模型会不会好？** 会，实测如此：同一份旧提示词，nano 86%，mini 100%。但代码核对值得保留：mini 也出现过“随机多报一个缺失字段”的错误（核对 2.1 那一轮在挑战集上掉到 97.4%），加了核对 2.2 的规则之后才挡住。

**没做到**
- 没有干净的测试分数。官方 30 条是开发集；挑战集是我写的，而且有两处修正参考过它上面的错误。
- GPT-5 nano 对“交期要提前但还没说哪天”这种说法 3 遍都读错（C15）。有意没修，留作已知失败。
- 同一配置重跑会差几个点，单次的 100% 不能当成“没有错误”。

**花费**：1,904 次调用，1.31 美元。

## 第 6 步 · 和模拟器讲道理（方向 5）
