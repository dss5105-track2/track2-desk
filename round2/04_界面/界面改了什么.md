# 界面第二轮：改了什么，为什么

代码在 `track2-desk-优化版/app/streamlit_app.py`，说明和演示脚本在 `track2-desk-优化版/docs/ui_guide.md`。截图在本文件夹的 `截图/`。

启动（在 `track2-desk-优化版` 目录下）：

```bash
streamlit run app/streamlit_app.py
```

## 改动一览

| 原来 | 现在 | 为什么 |
|---|---|---|
| 收件箱一张长表，按类型再按时间排 | 顶部五个分组（待确认、待决定、待追问、无法回答、已完成），每组带条数；组内**最紧的排最前** | 调度员一小时处理 30 条，先看会晚的 |
| 每行只有“下一步”，要点开才知道推荐谁 | 每行直接写：推荐车间、回货日、离交期还剩几天 | 不点开就能扫完一屏 |
| 只能逐条确认 | **一键确认稳妥的推荐**；紧单和会抢紧单车间的不在其中 | 13 条待确认里 7 条一键过，人只看剩下 6 条 |
| 卡片只给一个回货日 | 给两个：预计日期，和“如果返工最晚哪天”；返工也来得及是绿色，否则黄色 | 模拟里只报预计日期 94% 守约，报返工日期 100% |
| 解释只说“最早按时完成” | 一句“为什么”：例如它只做配件，把两类都能做的车间留给紧单；同时写出最快的是哪家 | 新规则不一定选最快的，要让人看得懂、能改选 |
| 不合格的车间收在折叠框里 | 直接列在候选表下面，带原因 | 少点一次 |
| 约束只写“谁、哪条消息” | 加上时间；如果约束是在这条请求之后才下的，卡片上写明，并显示请求刚到时的答案 | 原来 08:08 的请求卡片写着“被 08:48 的消息排除”，像是编的理由 |
| 确认后停在原地 | 确认后自动跳到下一条未处理的 | 省一次点击 |
| 追问、无法回答才有可复制的话术 | 每种情况都有“发到群里的话” | 调度员最后总要回群里 |
| Dev check 页对照旧的标准答案草稿 | 改成 Evaluation 页：说明四项评估和运行命令 | 旧草稿已作废，显示的分数会误导 |
| Simulator 页单个 seed | 可选 10 个 seed 平均；列出全部目标设置 | 老师要求 shock 报 10 个 seed 平均 |

## 我检查过的

- 用浏览器自动化走了一遍：载入、选行、一键确认、切换五个分组、打开 Simulator 和 Audit 页。页面没有报错，浏览器控制台没有错误。
- 截图我逐张看过。发现并修了八处：
  1. 收件箱右侧两列被挤掉；
  2. 按钮上的条数和实际确认的条数不一致；
  3. 批量确认后选中行和右侧卡片不同步；
  4. R09 的卡片在刷新后显示“有数字无法追溯”：解释里写了 Boss 那条约束的时间（08:48），但没有哪次工具调用输出过这个时间。现在约束本身作为一次工具调用记录下来，并加了测试：刷新和一键确认之后，30 条回复的数字仍然全部可追溯；
  5. “已完成”分组里“余量”一列是空的，现在按派出时的估算填上；
  6. 已派出的请求上还挂着“这条约束是后来才下的”提示，对已经结束的请求没有意义，现在只在未处理的请求上显示；
  7. “待追问”分组里“余量”一列显示 None，现在留空；
  8. Simulator 页的柱状图有 12 个策略，只显示了一半的名字，现在加高到每个策略都有标签。
