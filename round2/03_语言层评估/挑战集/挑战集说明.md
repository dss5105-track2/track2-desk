# 挑战集（38 条）：是什么，不是什么

## 是什么

38 条新的群聊消息，由 Claude 在第二轮**改语言层之前**写好，用来测系统在没见过的说法上的表现。同一份订单表和车间表，同一个早上（2026-04-01），按时间顺序处理，单独一本账。

| 文件 | 内容 |
|---|---|
| `challenge_requests.txt` | 38 条消息，格式和 `data/dispatch_requests.txt` 相同，编号 C01 到 C38 |
| `challenge_labels.csv` | 每条的标签：官方行为、内部子类、约束、回复必须包含什么、按早上队列算出的参考事实 |
| `challenge_parses.json` | 每条的手工解析（12 个字段） |
| `make_challenge.py` | 生成以上三个文件；每条的预期类别都用数据核对过 |

## 和官方 30 条的区别

- 换了说法：件数写成 `1,000`、`1.2k`；日期写成 `26 Apr`、`April 29`；“Anyone but BudgetWorks”“whoever has the fewest defects”“as fast as you can”。
- 多了两种官方 30 条里没有的情况：同一张单在同一个早上被要求派两次（C25）；要求外发一张早已完成的订单（C31）。
- 多了一种拒绝：点名的车间本身合格，但前面有人说过“暂时别给它”（C21）。
- 多了订单表里还没有的新活（C06、C24、C32）。

| 类别 | 条数 |
|---|---|
| 完整且能按时 | 6 |
| 带约束 | 6 |
| 完整但不可能按时 | 4 |
| 指代不清 | 5 |
| 缺数字或日期 | 4 |
| 点名的车间接不了 | 6 |
| 数据里没有答案 | 5 |
| 状态矛盾（重复派单、订单已完成） | 2 |

## 不是什么

- **不是留出集。** 留出集要由不碰提示词的同学手写（见 `../留出集骨架/`）。这一套是 AI 写的，而且写系统的也是 Claude，报告里必须单独标明，不能和留出集混在一起报。
- **不完全干净。** 各解析器在它上面的**第一次**运行（`../基线_改进前/`）是干净的。之后：
  - 规则解析器是看过它在这 38 条上的错误之后改的，所以规则解析器“改进后”的分数不算测试；
  - 路由里“新活要问细节”的修正也来自这 38 条；
  - LLM 的提示词 v2 和代码核对 2.0、2.1 只根据官方 30 条的错误设计，没有看 LLM 在这 38 条上的逐条错误；
  - 代码核对 2.2 的那条规则（点了单号、原文没提时间，就不接受模型说的“缺交期”）是在官方 30 条和这 38 条上都看到同一类错误之后加的。所以 2.2 在这 38 条上的分数是开发分数；
  - C15（“sooner than planned but haven't said when”）GPT-5 nano 每遍都错。这一条有意没有补规则，留作已知失败。

## 怎么跑

在 `track2-desk-优化版` 目录：

```bash
python eval/run_language_eval.py --inbox ../03_语言层评估/挑战集/challenge_requests.txt --labels ../03_语言层评估/挑战集/challenge_labels.csv --parses ../03_语言层评估/挑战集/challenge_parses.json --tag challenge38 --parser rules --out ../03_语言层评估/改进后
```

把 `--parser rules` 换成 `--parser llm --model gpt-5-nano --runs 3 --env <含 key 的 .env 路径>` 就是 LLM 版，会产生费用（每 38 条约 1 美分）。
