# 调度员界面说明与演示脚本（第二轮）

```bash
streamlit run app/streamlit_app.py
```

界面只负责展示和把点击转成 `desk/pipeline.py` 里的调用。所有交期、成本、排序都来自 `kernel/`，界面自己不算任何数字。

设计目标：调度员一早上有 30 条消息、一个小时。界面要让他先处理最紧的，稳妥的一键过，每条卡片前三行就能做决定。

## 页面结构

| 位置 | 内容 | 对应的评分点 |
|---|---|---|
| 左侧栏 | 目标选择（下面有一句话说明）、解析器选择、载入收件箱、重置、**常驻约束**（谁下的、哪条消息、几点、可解除）、各车间当前队列和今天已派件数 | 目标即配置；约束记录下达人 |
| Dispatch · 顶部 | 五个分组，带条数：待确认、待决定、待追问、无法回答、已完成。按调度员的处理顺序排 | 压力下先看要处理的 |
| Dispatch · 左半 | 当前分组的列表，**最紧的排最前**。每行直接写出决定：推荐车间、回货日、离交期还剩几天。新消息输入框 | 候选、估算、推荐一眼可见 |
| Dispatch · 右半 | 请求卡片，见下 | 解释可追溯 |
| Workshops | 车间登记册、当前队列图、“谁能接这批”查询 | 可查询的车间登记册 |
| Audit log | 账本记录（含返工时的最晚日期）、所有人工操作记录、下载 audit.json | 可审计的结构化记录 |
| Simulator | 官方模拟器实时运行：三个 baseline、简单规则分配器、全部目标设置；可切换 seed、是否取 10 个 seed 平均、是否 shock | 与 baseline 对比 |
| Evaluation | 四项评估是什么、怎么跑；当前目标下无人值守重放的结果 | 评估可复现 |

## 请求卡片：前三行

1. **问了什么**：订单、件数、品类、交期（还有几天）、请求人的要求（最快、避开某家、点名某家）。
2. **系统的决定**：推荐车间、回货日、离交期还剩几天、**如果这批返工最晚哪天**、成本。返工也来得及是绿色；来得及但返工就晚是黄色。
3. **为什么**：一句话。例如“返工也能按时；它只做配件，所以两类都能做的车间留给更紧的单”。

下面依次是：数字核查标记、候选车间表（回货日、剩余天数、返工日期、排队、加工、运输、成本、缺陷率）、不合格车间及原因（直接列出，不用点开）、操作按钮、可复制的群聊回复、工具调用明细。

| 情况 | 颜色 | 按钮 |
|---|---|---|
| 有按时方案，返工也来得及 | 绿 | 确认推荐车间；或从下拉框选别家 |
| 有按时方案，但返工就会晚（“tight”） | 黄 | 同上；不会被批量确认 |
| 没有按时方案 | 橙 | 接受延误并派出；或选别家；重谈交期；上报 Boss |
| 点名了不能接的车间 | 红 | 用替代车间派出；或选别家 |
| 需要追问 | 蓝 | 复制追问话术；指代不清时直接选订单；输入请求人的回答让系统重新处理 |
| 数据里没有答案 | 灰 | 复制回复话术；标记已回复 |
| 已派出 | 紫 | 改派；查看审计记录 |

## 一键确认

“待确认”分组上方有一个按钮：**Confirm N safe recommendations in one click**。

- 只确认“返工也来得及”的推荐。
- 交期紧的（黄色）不会被批量确认，排在列表最前，留给人逐条决定。
- 如果某条稳妥的推荐要用的车间，正好是某条紧单也要用的，它也会被留下，提示先决定那条紧单。
- 按到达顺序逐条确认，每确认一条就按最新账本重算下一条；途中不再稳妥的会跳过。
- 这仍然是一次人工确认：按钮上的数字就是会派出的条数，结果会列出每条去了哪家。

官方 30 条载入后：13 条待确认里，一键确认 7 条，6 条留给人（3 条紧单，3 条会占用紧单要用的车间）。

## 约束是什么时候下的

“本周别给 QuickStitch”是 R12 在 08:48 说的。界面一次载入全部消息，所以 08:08 的 R04 打开时这条约束已经存在。界面的处理：

- 仍然对所有**未处理**的请求生效（现在派单就该遵守）。
- 但卡片上会写明：这条约束是之后才下的，因为请求还开着所以适用；并显示这条请求刚到达时的答案是什么。
- 评估用的无人值守重放按时间顺序逐条处理，不会把约束用到更早的请求上。

## 5 分钟演示脚本（Sprint 2 视频可直接用）

1. **载入收件箱。** 30 条进来，没有派出任何一单。指五个分组的条数：13 条待确认、7 条待决定、7 条待追问、3 条无法回答。
2. **一键确认。** 点按钮，7 条稳妥的派出，顶部列出每条去了哪家。讲：剩下 6 条是系统认为需要人看的。
3. **R12，紧单。** 黄色：GiantWeave 周五回货，正好卡在交期当天，返工就晚一天。指左侧栏的约束：QuickStitch 本周不接新单，Boss 在 R12 下达。点确认。
4. **“已完成”里的 R04，为什么不选最快的。** 它去了 Little Loom 而不是最快的 Nimble Needle：Little Loom 只做配件，返工也来得及，把两类都能做的车间留给紧单。审计记录里写着当时最快的是哪家。
5. **R21，没有好选择。** R12 占用 GiantWeave 之后，R21 从黄色变成橙色，移到“待决定”：最早也晚 1 天。解释里写着“如果解除对 QuickStitch 的禁令，可以按时”。点左侧 Lift，R21 回到可按时。讲这就是把决定权交还给人。
6. **R08，拒绝。** FreshStart 单批上限 300，请求是 400 件。给出替代并可一键派出。
7. **R03，追问。** TrendCart 有 6 单在产，系统列出候选而不是猜。直接选订单，新请求自动生成。
8. **R18，无法回答。** ORD-999 不存在，系统说查不到，不编。
9. **Audit log。** 每一次确认、批量确认、改派、解除约束都有记录，可下载。
10. **Simulator。** 打开 10 个 seed 平均。讲：官方数据上我们和简单规则迟交率相同、迟交天数减半；数据一变我们更好，证据在评估报告里。

## 部署成公开 demo 链接

Sprint 2 首页需要可打开的 demo 链接。Streamlit Community Cloud 免费：

1. 用仓库所有者账号登录 https://share.streamlit.io ，授权读取 GitHub。
2. New app，仓库选 `dss5105-track2/track2-desk`，分支选合并了本轮改动的分支，入口文件 `app/streamlit_app.py`。
3. 部署。默认使用规则解析器，不需要任何密钥。
4. 部署后用另一台电脑、不登录的浏览器打开链接，确认能载入收件箱并确认一条。

**公开 demo 里不建议放 API key。** 链接是公开的，任何人都能触发调用、花掉额度。如果一定要在线演示 GPT-5：在应用的 Settings → Secrets 里填 `OPENAI_API_KEY`，先在 OpenAI 后台给这个 key 设很低的月度上限，演示完就删掉。不要把 key 写进仓库。

公开链接意味着任何人都能点确认。会话之间互不影响，刷新页面或点 Reset 就回到初始状态。
